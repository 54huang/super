# 1 · 口播稿与 SRT

> 节点 N10 的核心主张：**旁白先存在，镜头时长才不是编出来的**。所以这一步必须先把文案写死。

## 口播稿（125 字 / 30 秒）

```
你以为 C++ 的析构函数，只是清理内存？
看这段代码：打开文件、读数据、抛异常。
崩了之后，close 谁来调？
没有人写，但它一定会被执行。
因为对象在栈上，离开作用域就死，死前必调析构。
这就是 RAII：把资源的生命周期，绑在对象的生命周期上。
所以 C++ 里没有 finally，也不需要 finally。
```

写作上的三个刻意选择：

| 位置 | 手法 | 为什么 |
|---|---|---|
| 第 1 句 | 反问钩子 | 前 3 秒必须让"以为自己懂的人"停一下 |
| 第 3 句 | 制造缺口（"谁来调？"） | 悬念撑过 8-12 秒的流失高峰 |
| 第 5-7 句 | 先机制后命名 | 先让他看懂，再给术语，完播率和收藏率都更高 |

## 标准 SRT（直接可导入剪映 / 交给 N10 的流程）

```srt
1
00:00:00,000 --> 00:00:04,000
你以为析构函数只清内存？

2
00:00:04,000 --> 00:00:08,000
开文件、读数据、抛异常

3
00:00:08,000 --> 00:00:12,000
崩了之后，close 谁来调？

4
00:00:12,000 --> 00:00:16,000
没人写，但它一定会执行

5
00:00:16,000 --> 00:00:22,000
离开作用域，死前必调析构

6
00:00:22,000 --> 00:00:26,000
把资源绑在对象生命周期上

7
00:00:26,000 --> 00:00:30,000
所以 C++ 不需要 finally
```

## 时间码校验（N10 的三条硬规则）

| 检查项 | 结果 |
|---|---|
| 是否无缝覆盖 0–30 秒 | ✅ 4+4+4+4+6+4+4 = 30，无空洞无重叠 |
| 是否贴合平台档位 | ✅ 全部为 4 秒或 6 秒 |
| 音画差值是否显式处理 | ✅ 无残差（合计正好 30.000） |
| 单条字幕是否 ≤16 字符（不含空格） | ✅ 最长 15（S07「所以 C++ 不需要 finally」） |
| 断句是否在语义停顿处 | ✅ 无跨镜断句 |

> 如果旁白念完是 28.4 秒，多出的 1.6 秒不要"平均摊"给 7 个镜头 —— 应该给收尾镜（S07）延长到 5.6→6 秒档位，或删掉一句冗余的话。**时间码是硬约束，画面是软约束**。
