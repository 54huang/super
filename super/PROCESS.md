# 全流程

从"什么都没有"到"能导出帧的片子"，一共 8 步。每步都写清 **输入 / 动作 / 输出 / 验收**，以及**这一步最容易错的地方**。

整个流程可复现：本仓库里每一份产出都对应下面某一步的输出文件。

---

## 0 · 起点

- 输入：一句话需求（"我要抖音向的 AI 视频提示词素材，能直接喂模型改善画面与镜头"）
- 输出：一条**边界声明**（收什么、不收什么）
- 本次的边界：

  | 收 | 不收 |
  |---|---|
  | 提示词库、镜头/运镜词表、画面约束、分镜脚本、负面词、代码出片方案 | 模型微调、LoRA、推理加速、API 中转站、MP4 成片下载 |

> **最容易错**：不写边界就开始搜。搜索结果里 API 中转站和"prompt gallery"垃圾站的占比极高（实测在 "kling prompt" 这类词下超过六成），没有边界就会被噪音带偏。

---

## 1 · 检索（广度优先）

- 输入：边界声明
- 动作：用 GitHub Search API 跑多组检索词，按 stars 排序，每组取 30 条

```bash
# 实际使用了 36 组检索词，分 4 批跑；未认证的 search API 限流 10 次/分钟
curl -s "https://api.github.com/search/repositories?q=sora+prompt&sort=stars&order=desc&per_page=30"
```

- 输出：`675` 个去重仓库的原始元数据（repo / stars / lang / pushedAt / topics / desc）
- 验收：去重后数量 ≥ 300，且至少覆盖 5 类不同意图（通用库、镜头、分镜、单模型、代码出片）
- **最容易错**：只搜一个词。搜 "ai video prompt" 会得到 3600 个结果但全是同一个模子；必须加上"运镜/分镜/剧本/动画引擎"这些**意图词**才能捞到不同分层的东西。

---

## 2 · 筛选（四条硬标准）

- 输入：675 个候选
- 动作：逐条过四条标准，任一不满足即淘汰

  1. 交付物是**文本资产**（md / 词表 / 模板 / Skill），不是权重、不是成片；
  2. 有**镜头维度**（景别/机位/运镜/时长），不只是"画什么"；
  3. 能**原样粘贴**进模型，不需要先部署服务；
  4. **仍在更新**（2026 年仍有提交，或内容不过期）。

- 输出：50 个仓库
- 验收：每个都通过 GitHub API 核对过 `full_name` 真实存在；对标记为节点的额外拉取目录列表与 README 确认结构
- **最容易错**：把"星多"当"好"。本轮 2.8k 星的 Seedance 库和 48 星的运镜库，后者对"镜头控制"的价值更高。星数是**热度**，不是**匹配度**。

---

## 3 · 分类与建索引

- 输入：50 个仓库
- 动作：按**你在链路的哪一步需要它**分类，而不是按模型名分

  ```
  01 通用总库 → 02 镜头 → 03 美学 → 04 分镜 → 05 单模型 → 06 抖音工作流 → 07 程序化 → 08 反推
  ```

- 输出：
  - `library/<分类目录>/README.md`：收录逻辑 + 全部分仓表格（来源 / 用途 / 节点标记）+ 取用顺序
  - `library/00_起点/` 四份导航：全仓清单、节点总表、需求速查、可直接粘贴模板
  - `docs/research/repos.snapshot.json`：机器可读快照
- 验收：8 个目录齐全、每个目录有 README、24 个节点各有 `Nxx_*.md`、编号连续（`tests/library.test.mjs` 自动核对）
- **最容易错**：按模型分类。抖音的生产链路是"想法 → 文案 → 分镜 → 单镜提示词 → 出片"，按模型分类会让你在每个模型目录里重复放一遍"怎么切镜"。

---

## 4 · 选题与口播

- 输入：分类好的素材（此时才知道"什么内容适合用什么手法"）
- 动作：定题材 → 写口播稿 → 控制字数与语速

  ```
  125 字 ÷ 30 秒 ≈ 4.2 字/秒（讲解类舒适区 3.8–4.5）
  结构：钩子（反问）→ 举证 → 制造缺口 → 反转 → 机制 → 命名 → 结论
  ```

- 输出：`campaign/30s-raii/1_口播稿与SRT.md`（口播稿 + 标准 SRT + 时间码校验表）
- 验收：能算出总时长；断句在语义停顿处；单条字幕 ≤16 字符（不含空格）
- **最容易错**：先想画面再配音。画面是为旁白服务的，反了就会得到一堆漂亮但听不懂的镜头。

---

## 5 · 切镜与分镜表

- 输入：SRT
- 动作：按**时间码**切镜（不是按字数、不是按感觉），时长吸附到平台档位

  ```
  平台单镜档位：4 / 6 / 8 / 10 秒
  本片：4+4+4+4+6+4+4 = 30.000，无缝覆盖、不重叠、不留空
  ```

- 输出：
  - `campaign/30s-raii/2_分镜表.md`（人读：景别/机位/运镜/功能/字幕 + 节奏检查）
  - `specs/shots.json`（机读：同样的事实，给测试和渲染器用）
- 验收：时间码闭合、时长在档位内、字幕字数、每 8 秒一次变化（`tests/storyboard.test.mjs` 自动核对）
- **最容易错**：写"5.5 秒"这种时长。平台会吸到 6 秒，音画立刻错位；所有时长必须贴着档位取整。

---

## 6 · 分流生产

这是整个流程的关键分叉：**同一张分镜表，不同镜头走不同的生产方式。**

- 输入：`specs/shots.json`
- 动作：按"正确性要求"分流

  | 判据 | 走 AI 生成 | 走代码渲染 |
  |---|---|---|
  | 画面里有需要**精确正确**的内容（代码、结构图、公式） | ✗ | ✓ |
  | 有需要精确的**时序/物理**（落体、盖章、连锁） | ✗ | ✓ |
  | 只需**氛围与转场** | ✓ | ✗ |
  | 需要**真实人物/材质** | ✓ | ✗ |

  最初的分流：S03 / S05 / S06 → 代码；S01 / S02 / S04 / S07 → AI。
  **实际执行时四镜全部改回代码**，最终 7 镜都由渲染器产出（见 CHANGELOG 1.4.0）。
  原因不是判据错了，是 AI 那一路拿不到稳定产出：单镜内的先后时序、
  以及"红笔划掉再批注"这种精确动作，生成式模型一次给不齐。
  这条判据需要补一句：**凡是镜内有时序的，都归代码**。

- 输出：
  - `campaign/30s-raii/3_逐镜提示词.md`（AI 镜头：五段式 + 全局风格块 + 负面清单 + 首帧描述）
  - `renderer/`（代码镜头：逐帧渲染器）
- 验收：AI 镜头的提示词能整段粘贴；代码镜头的时长与 `specs/shots.json` 一致
- **最容易错**：全交给 AI。三镜里有两镜（代码、结构图）AI 几乎必崩，会耗掉一半时间在抽卡上。

---

## 7 · 出片与验收

- 输入：两条产线的素材
- 动作：

  ```bash
  # 代码镜头：逐帧导出 PNG → 合成
  ffmpeg -framerate 30 -i S05_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 16 s05.mp4
  # AI 镜头：每镜 3–4 次抽卡（S03/S05 属高危镜，留 6 次）
  ```

- 输出：`campaign/30s-raii/4_出片与验收清单.md` 的填写结果（单镜检查 + 全片检查 + 迭代记录）
- 验收：单镜 6 项、全片 6 项全部打勾（清单在文件里）
- **最容易错**：只看单镜不看拼起来的效果。色调跳、字幕越界、节奏闷，都是拼起来才暴露的问题。

---

## 8 · 归档与复盘

- 输入：这次的产出与踩坑
- 动作：
  1. 把新踩的坑写进 `4_出片与验收清单.md` 的「翻车对照表」；
  2. 把改过三次以上仍有效的做法，写进 `library/00_起点/可直接粘贴模板.md`；
  3. 若改变了长期做法（换美术方向、换分工判据），补一篇 `docs/decisions/ADR-<编号>-<标题>.md`；
  4. 跑 `npm test` 确认没有把仓库搞坏。
- 输出：更新后的文档 + 一篇 ADR（如有）
- 验收：`npm test` 全绿；任何新增的"规则"都有对应的断言或 ADR
- **最容易错**：复盘只写"下次注意"。没有落成文件的经验等于没发生——三个月后你会一模一样地再错一次。

---

## 流程全景

```
边界 → 检索(675) → 筛选(50) → 分类(8类/24节点) ─┐
                                              ├→ 选题 → 口播(125字) → 切镜(7镜/30s)
                                              │            │
                                              │            ├→ 分流 A：AI 生成 → 提示词
                                              │            └→ 分流 B：代码渲染 → 渲染器
                                              └────────────→ 出片 → 验收 → 归档(ADR)
```

每一条箭头都对应仓库里一个真实文件。没有箭头的环节，说明还没做或还没验证。
