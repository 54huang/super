# super

**三种已经跑通的视觉风格，一条能走完的制作流程。仓库同时是这条流程的记忆。**

不是教程集，也不是素材站——它记录的是"用这套方法真做出了一条 30 秒的片，中间踩了什么"。所以风格能直接拿去用，流程能直接照着走，坑都写在明面上。

---

## 一、先挑风格

风格不是一张皮，是一整套画面约束：色值、线宽、字号、能表达什么、不能表达什么。挑定之后才知道后面该调哪些参数。

| 风格 | 介质 | 一句话 | 擅长 / 别用 |
|---|---|---|---|
| **02 制图台** | 暖白纸 + 墨线 + 朱红批注 | 冷内容写在暖纸上，批注是人的动作 | 代码、公式、协议、条文这类精确符号系统 / 别用于动态过程与对比 |
| **03 示波器** | 黑玻璃 + 荧光波形 + 双通道 | 横轴是时间，两条线的落差就是论证本身 | 表达两条序列的关系（正确／错误、承诺／兑现）/ 别用于信息流首帧、展示"是什么" |
| **04 黑板粉笔** | 墨绿板面 + 粉笔灰 + 木框 | 每一笔有先后，划掉和写下的动作同等重要 | 展示推导过程（先写、发现不对、划掉重写）/ 别用于精致成品感、精确数据、横屏 |

三种风格换的不是配色，是**介质**：发光 → 纸面 → 玻璃 → 粉笔灰。介质决定了这一版能做什么动作。

跑 `npm run dev` 起本地服务，**根路径就是风格展示台**：三种风格并排给你看，每种都配一段可直接复制的引导块——色值、线宽、字号、语汇一次给全，拿去喂 AI 或者直接落成代码常量都行。

每种风格各有一个可交互的工作台：

| 工作台 | 风格 | 能力 |
|---|---|---|
| `renderer/index.html` | 制图台 | 七镜全片连播 30 秒；**切镜**、**逐帧**、拖**时间轴**、**导出** PNG 序列与整片 |
| `renderer/scope.html` | 示波器 | 八镜；同样能**切镜**、**逐帧**、拖**时间轴**、**导出** |
| `renderer/board.html` | 黑板粉笔 | 八镜；同上，另加**安全区**与**帧号**开关（导出时自动关帧号） |

不联网、不装依赖。键盘：空格播放暂停，← → 逐帧。

每种风格还各有一张卡（`docs/cases/`），固定八节，含**已知缺陷**和**换个题材怎么改**——复用之前先知道它会在哪裂开。

## 二、再走流程

顺序不能换。第二步决定第七步的长度。

| # | 步骤 | 关键约束 |
|---|---|---|
| ① | 定边界 | 画幅、帧率、总时长写死 |
| ② | 写口播稿 | 125 字 ÷ 30 秒 ≈ 4.2 字/秒，**总时长在这一步就锁死了** |
| ③ | 切镜分镜 | 按时间码切，时长吸附 4/6/8/10 秒档位 |
| ④ | 选美术方向 | 就是上面那些约束，抄成常量，不要边画边调 |
| ⑤ | 写渲染器 + 锁契约 | 同一个 `t` 必出同一帧；规则要变成会失败的断言 |
| ⑥ | 渲 900 帧 | 不用开浏览器，约 5.5 分钟 |
| ⑦ | 合成并验收 | ffmpeg 出 mp4，时长必须整 30.000 秒 |

**不含配音**——当前成片是无声的，那一段单列在手册文末「后续优化」，没有混进主流程。

每步的输入、命令、产出文件、验收数字写在 `docs/REPRODUCE.md`（操作手册）；为什么这么排、最容易错在哪写在 `PROCESS.md`（方法论）。两份冲突时以操作手册为准，它是按最后一次真实出片校准的。

从零到一条 mp4 的最短路径：

```bash
npm test                                                       # 基线 65 项必须全绿
node scripts/render-offline.mjs --style v2 --all --out frames   # 900 帧，约 5.5 分钟
ffmpeg -framerate 30 -i frames/v2_%04d.png \
       -c:v libx264 -pix_fmt yuv420p -crf 16 -y out.mp4       # 约 30 秒
```

## 三、仓库还是这套流程的记忆

做完一次就散掉的经验，三个月后会一模一样地再错一遍。所以这里留了五类痕迹：

| 记什么 | 在哪 | 强制手段 |
|---|---|---|
| 为什么这么定 | `docs/decisions/` 六篇 ADR，每篇含**代价** | 测试检查每篇都有「状态/背景/决定/后果」四段 |
| 验过什么、**没验什么** | `docs/verification.md` | 未验证项单独成表，不假装覆盖 |
| 风格会怎么坏 | `docs/cases/` 每张卡的「已知缺陷」 | 测试检查缺陷段不是空壳 |
| 每次改动连坑一起记 | `CHANGELOG.md` | 比如「浏览器能画中文不等于 Node 能画」 |
| 内容必有来源 | `library/`、`docs/research/` | 测试检查 50 条记录都有 repo/url/用途 |

规则没有停在文字上：`npm test` 把能自动核对的全变成会失败的断言。**断言也要被验证**——故意改坏一处，看它是否真的变红；不红说明这条断言是假的。

## 目录

```
super/
├── index.html        风格展示台（仓库门面）
├── renderer/         渲染器：v3 示波器 / v2 制图台 / v1 留档
├── campaign/         一条 30 秒片的全部档：口播 → 分镜 → 提示词 → 验收
├── specs/            契约层：分镜规格、设计令牌（机器可读）
├── tests/            证据层：把说过的规则变成会失败的断言
├── scripts/          离线渲染与本地服务
├── docs/
│   ├── REPRODUCE.md  操作手册：七步，每步有命令和数字
│   ├── cases/        风格卡（八节，含缺陷与迁移方法）
│   ├── decisions/    决策记录 ADR-001 ~ 006
│   ├── samples/      展示台用的样品帧
│   ├── research/     采集方法与仓库元数据快照
│   └── verification.md  验证记录
├── library/          研究资产：50 仓索引 + 24 节点（**不在产线上**，见下）
├── PROCESS.md        方法论
├── ARCHITECTURE.md   分层原则与扩展方式
└── CHANGELOG.md
```

`library/` 那一半文件量要说明一下：它是**方法来源**，不是素材供应商。`grep -r "library/" --include="*.js"` 在整个代码库里只命中一句注释——这 50 个仓库没有一个文件被渲染器用过。复现出片不需要它。

## 一点边界

- 提示词与素材版权归各仓库作者，商用前看各自 LICENSE（多为 MIT / CC BY 4.0 / Apache-2.0）。
- 星数、语言、最近提交为 2026-10-28 的 GitHub API 快照，会过期；`docs/research/` 里写了怎么复查。
- 画面观感未被自动验证，这一项只能靠人看——诚实写在这里，而不是假装测试覆盖了。
