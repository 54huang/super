# ADR-001 · 提示词资产做成仓库，而不是收藏夹

**状态**：已采纳（2026-10-28）

## 背景

需要维护 50 个外部仓库的提示词资产。最省事的做法是浏览器书签 + 一个 Excel，或者直接丢进笔记软件的剪藏。

但这类资产的真实问题是**半年后无法复用**：书签只有链接，没有"这个仓能解决什么"；剪藏只有正文，没有"当时为什么选它"。等要做下一条片子时，等于从零再搜一遍。

## 决定

做成 git 仓库，且每个仓库条目必须包含三样东西：**来源（可点开的链接）、用途（解决链路哪一步）、取用路径（先看哪个目录/文件）**。

同时把这些事实同步到 `docs/research/repos.snapshot.json`，让数量、编号、节点、用途可以被测试检查。

## 后果

- **收益**：换机器、换人、换时间点，都能拿到同一份上下文；能用 `git log` 看出判断是怎么变的。
- **收益**：因为有 JSON 快照，"50 个仓 / 24 个节点"这句话是被测试保证的，不是手写的。
- **代价**：新增一个仓库要改 3 个地方（分类 README、全仓清单、snapshot），比收藏多花两分钟。用测试兜住遗漏。
- **代价**：星数与更新时间会过期。作为对冲，`docs/research/采集方法.md` 记录了复查方式，README 里明确写了快照日期。
