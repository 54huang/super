# ADR-002 · 资产分三层：研究 / 生产 / 实现

**状态**：已采纳（2026-10-28）

## 背景

第一版把所有东西放在一个目录里：50 个仓的索引、一条片子的口播稿、渲染器代码、以及若干截图。文件数 45 个，看起来"整理过了"。

实际使用时立刻出问题：搜索"运镜"，同时命中"某个外部仓库有运镜词表"和"我们这条片在 8 秒用了推镜"——一个是**输入**，一个是**产出**，混在一起就分不清哪句是抄的、哪句是判断。

## 决定

按**在链路中的角色**分三层，依赖方向单向：

```
library/（研究，外部知识的索引）   ← 谁都不依赖
campaign/（生产，这次的处理结果）  ← 引用 library
renderer/（实现，这次用的机器）    ← 与 specs 对齐
```

三者都不互相 import，唯一的连接点是 `specs/`（机器可读的事实）和 `tests/`（证据）。

## 后果

- **收益**：换美术方向时，改动范围是明确的（specs + renderer + 该镜头的提示词），不会漏。ADR-004 就是靠这个边界在半小时内完成的。
- **收益**：素材库可以无限扩充而不影响片子；片子可以换一条而素材库不动。
- **代价**：同一条信息会出现在两处（`02_分镜表.md` 给人看，`specs/shots.json` 给机器看）。用测试强制两者一致，不一致就红。
- **代价**：目录层级变深，新人第一次进来需要读 `ARCHITECTURE.md` 才知道东西在哪。接受，因为没有分层的话连自己都要猜。
