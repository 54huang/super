# 案例 03 · 示波器

**状态：现役。** 实现 `renderer/src/scope-renderer.js`（899 行），页面 `renderer/scope.html`，八镜 P01–P08。

## 一句话

把资源生命周期画成两条电压曲线：横轴是时间，CH1 回到基线，CH2 停在半空，落差本身就是论证。

## 视觉构成

| 项 | 值 |
|---|---|
| 玻璃底 | `#0C1310` → `#030605`，四角径向压暗 |
| 通道一 | 荧光绿 `#5EF2A0` |
| 通道二 | 琥珀 `#F2A93B` |
| 触发／异常 | 红 `#E8503A` |
| 正文 | `#CBDAD0`／次级 `#6E8B7A` |
| 网格 | 10 列 × 12 行，细线 `#14332A`，主格 `#1F5138` |
| 波形区 | x 96–984，y 316–1452 |
| 通道基线 | CH1 = 700，CH2 = 1148，振幅 248 |
| 辉光 | 三段描边 5.5 / 2.6 / 1px，透明度 0.10 / 0.26 / 1.00 |
| 时钟 | 八镜各 4 秒，共 32 秒 |

## 实现入口

- `renderer/src/scope-renderer.js` — 全部绘制与八镜脚本
- 布局常量 `L`（x0 / x1 / yTop / yBot / ch1 / ch2 / amp）
- 引擎导出 `window.Scope`：`init` `select` `seek` `toggle` `onChange` `exportFrame` `exportSequence` `renderAt`
- `renderAt(shotIdx, ms)` 是给测试用的：脱离动画循环直接渲染某一时刻

## 关键技术点

**辉光用三段描边，不用 `shadowBlur`。** 同一个发光效果，`shadowBlur` 是软件高斯核，成本随「面积 × 核半径」上升；改成 5.5px(α .10) / 2.6px(α .26) / 1px(α 1.0) 三层叠加，成本是常数。`tests/scope.test.mjs` 有断言守着这一条。

**噪声用正弦叠加，不用随机数。** `sin(t·137.5 + seed)` 一类固定频率叠加，既有信号毛刺感又完全确定。用 `Math.random` 会让同一时刻渲染出不同帧，逐帧导出时整条波形在抖。

**波形是数据，不是代码。** 每镜的波形就是一个 `events` 数组（`{t, v}` 折线顶点），`tracePoints()` 统一插值加噪。加镜头只需要加数据，不改绘制逻辑。

**写头提亮模拟扫描。** 波形整体画一次（暗），靠近写头 190px 的尾段用 `lighter` 混合再画一次（亮）。这是模拟示波器荧光余晖的核心，缺了它画面就是"静态折线图"。

## 已知缺陷

这张卡记下来，复用前先看一眼：

| 缺陷 | 位置 | 说明 |
|---|---|---|
| 通道标签无条件绘制 | `drawAxisLabels` 第 170–171 行 | P01–P05 没有 CH2 波形，左边却标着 CH2。真仪器未接入的通道不该显示 |
| 上电刻度溢出 | P01 的 `drawAxisLabels` | 网格只展开 55%，时间刻度已经全画，刻度飘在网格外 |
| 水印与测量框重叠 | 水印 `y = L.yTop - 16`，测量框 `by = 300` | 两者都在 y=300、右边界都是 984，会压在一起 |
| 底部正文基线不统一 | 散落在 1614 / 1646 / 1652 / 1686 / 1688 / 1766 | 六个数，同一台仪器读数不该跳高度 |
| 没有字号令牌 | 全文 | 12–46px 十余种临时值，对比 02 的六级体系是倒退 |
| 通道色兼任语义色 | 全局 | 绿色既是 CH1 通道色又是"配对成功"，琥珀既是 CH2 又是"泄漏"。真仪器的通道色是中性的，不承载褒贬 |
| P04 抖动晃到铭牌 | P04 的 `c.translate()` 在 `drawPlate` 之前 | 信号不稳不该让仪器外壳跟着晃，隐喻层级用错 |

最后两条不算 bug，是设计选择出了问题。前五条是实打实的实现缺陷。

## 什么场合用

- 要表达**两条序列的关系**：正确／错误、承诺／兑现、请求／响应、before／after、控制组／实验组。
- 要表达**时间上的配对**：开始与结束是否闭合，中途断开会不会漏。
- 需要在**一个画面里同时给出结论和证据**：CH2 那条不落的线既是证据也是结论。
- 观众熟悉仪器语汇，或有字幕兜底。

## 什么场合别用

- **短视频信息流，尤其是首帧。** 深色画面在偏亮的浏览环境里对比度低，"停下来"的能力弱于 02 的暖白纸。这条是这一版最实际的损失。
- **需要表达"是什么"而不是"怎么样"。** 示波器天生只讲变化，不讲形态。要展示一个对象的结构，它帮不上忙。
- **没有字幕兜底时。** 时基、触发、通道、"停在半空"——不懂示波器的人看不出 CH2 意味着什么。02 的纸面批注是自解释的，这一版不是。
- **中文文字量大的画面。** 荧光绿配黑底，中文笔画细节不如墨压纸清楚，21px 以下会糊。

## 换个题材怎么改

可迁移性比 02 更广，因为它的骨架是抽象的：

1. **换通道语义。** CH1／CH2 可以代表任何一对可比对象：手动管理 vs RAII、旧方案 vs 新方案、承诺 SLA vs 实际延迟、说法 vs 做法。**两条线的落差有多直观，这一版的论证就有多强。**
2. **换 `events` 数组。** 波形形状就是叙事。抬起来是"占用"，平着是"持有"，阶梯下降是"逐层释放"，停在半空是"泄漏"。把这四种形状的组合记熟，绝大多数"配对"题材都能套。
3. **换时基档位与量程。** 铭牌上的 `500ms/div`、`1.0V/div` 是装饰性真实，改成你的量纲（`10req/s`、`1MB/div`）立刻贴合新题材。
4. **换测量框的项目。** `ΔT`、`DTORS`、`LEAKED` 都是可替换的读数项，保持"键值右对齐"的版式即可。

不要改的是：**网格密度、双通道基线间距（必须大于振幅）、写头提亮**。这三个决定了它"像仪器"而不是"像折线图"。

改造时顺手把上面「已知缺陷」前五条一起修掉——它们是这一版的欠账，不是这套方法的一部分。

## 风格引导块

换题材时不用重读上面全部，把这段整块复制走即可——喂给 AI 是风格约束，落成代码是常量表。

```
视觉：实验室示波器，黑玻璃面板。底色 #0C1310→#030605；
网格横向 10 格，绿灰刻度线，透明度不超过 0.08。
通道：CH1 荧光绿 #5EF2A0，CH2 琥珀 #F2A93B，两条基线间距大于振幅。
辉光：用 5.5px / 2.6px / 1px 三段描边叠出，不要用 blur 或阴影滤镜。
读数：全等宽字，13px 小号，大写英文；时基 / 触发 / 通道标签齐全。
语汇：扫描束、光标、测量框、CAL 标记。要像仪器，不要像科幻 UI——
不要渐变光斑，不要霓虹紫，不要圆角卡片。
```

配套的三条硬约束：

- 双通道基线间距必须大于振幅，否则两条线会互相穿过，落差就读不出来了。
- 辉光只能用叠描边，不能用 `shadowBlur`——后者在大画布上会把每帧成本拉高数倍。
- 中文别超过 21px 以下的小号：荧光绿配黑底，中文笔画细节撑不住。
