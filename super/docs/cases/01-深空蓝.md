# 案例 01 · 深空蓝

**状态：弃用留档。** 代码在 `renderer/legacy/shot-renderer.v1.js`（674 行），不参与现役构建，但在测试白名单内。

## 一句话

深色渐变底上，青色线框立方体随代码执行翻转、碎裂、重组——把内存对象画成一个发光的几何体。

## 视觉构成

| 项 | 值 |
|---|---|
| 底色 | `#0B1220` → `#05070C` 纵向渐变 |
| 主色 | 青 `#22D3EE` |
| 强调 | 红 `#F43F5E`（异常、爆裂） |
| 卡片底 | `#0F172A` |
| 正文 | 白 `#E2F8FF` |
| 主体 | 线框立方体（12 条棱，可绕 Y 轴旋转） |
| 质感 | 全部靠 `shadowBlur` 发光，19–40px |
| 粒子 | 爆裂时 200–300 颗点光，带极短拖尾 |

## 实现入口

`renderer/legacy/shot-renderer.v1.js`

- `drawBG(c, t)` — 渐变底 + 缓慢流动
- `drawCube(c, cx, cy, size, rotY, opt)` — 线框立方体，带棱边高亮
- `drawCard(c, cx, cy, opt)` — 浮动卡片
- `drawS03` / `drawS05` / `drawS06` — 三镜各自的编排
- 常量 `C` 在第 32 行

## 关键技术点

**发光全部用 `shadowBlur` 实现。** 全文件出现 10 处，取值 18 / 20 / 22 / 26 / 30 / 40。这是这一版最大的技术负债：软件高斯核，成本随「面积 × 核半径」上升，字号一大就掉帧。

**立方体为什么飘。** 第一版没写重力与接触面，立方体在画面里平移，像贴图在滑动而不是物体在动。这是提示词和代码共同的问题：只描述了"移动"，没描述"落地"。

## 已知缺陷

| 缺陷 | 说明 |
|---|---|
| 发光全靠 `shadowBlur` | 全文 10 处，18–40px。软件高斯核，成本随面积 × 核半径上升，字一大就掉帧 |
| 立方体飘着走 | 没写重力与接触面，物体在画面里平移，像贴图在滑动而不是东西在动 |
| 深色高饱和久看疲劳 | 30 秒后眼睛累，不适合长内容 |
| 发光字会糊 | 深底上的高饱和文字边缘发虚，中文尤其明显 |

## 什么场合用

几乎没有了。真要用的场景只有一个：需要和「市面上常见的 AI 生成科技画风」保持一致时。

## 什么场合别用

- **短视频信息流。** 这一版被判「太普通」，判的不是执行，是选择：青色霓虹 + 线框立方体是 AI 视频的默认答案，训练数据里全是这个。观众一天能刷到几十条同款。
- **需要长时间观看的内容。** 深色高饱和，30 秒后眼睛疲劳。
- **需要承载文字的画面。** 发光字在深底上会糊，中文尤其。

## 换个题材怎么改

**结论是：不建议改。** 这一版的参数本身没问题（色值和谐、层次清楚），问题在于它表达的是"科技"，而"科技"是所有题目里最容易撞车的答案。

如果非要用，三步：

1. **换色相。** 它没有强绑定的语义，青改紫、改橙都成立，改完还是"科技感"。**正因为它可以随便换色，说明它没有观点**——这是判断一个视觉方向值不值得复用的标准：能随便换色的方案，通常谁用都一样。
2. **别再用 `shadowBlur` 做发光。** 换成案例 03 的三段描边法（宽而淡 + 中 + 细而亮），成本从"随面积 × 核半径增长"变成常数，字放大也不掉帧。
3. **把发光面积压到画面 10% 以内。** 这一版真正的问题不是颜色，是整屏都在发光、没有视觉落点。留一处亮，其余压暗，辨识度立刻上来。
