# 案例 04 · 黑板粉笔

**状态：现役。** 实现 `renderer/src/board-renderer.js`（1354 行），页面 `renderer/board.html`，八镜 B01–B08。

## 一句话

把一条推导写在黑板上：先写对的一行，发现出事，红笔划掉，蓝笔重写——介质不是纸也不是屏幕，是粉笔灰，所以每一笔都有先后。

| 木框 | 52px 四边，底色 `#3B2A1E`，130 条随机竖纹 + 70 条横纹叠出木纹，内沿一道 5px 暗边 |

## 关键技术点

**粉笔的笔芯是短划痕拼出来的，不是一条实线。** 这是整张卡最重要的一条。一条 `stroke()` 画出来的线，边缘再抖也是"马克笔"。做法是沿弧长撒短划痕：段长 5–11px、间隔 0.6–2.8px、粗细与透明度各自抖动，叠出来天然断续、有颗粒。外缘再撒一层更淡的划痕当粉笔灰。三件事一起做，才有"粉笔写在粗糙表面"的质感。

**断续不能用 `destination-out`。** 把线挖断确实像粉笔，第一版就是这么做的，视觉上最像——但 `destination-out` 挖的是像素本身，导出 PNG 时变成透明，合成到视频里就是一片黑斑。而且在小图上看不出来，只有放大到 100% 才发现。`tests/board.test.mjs` 有一条断言专门拦这个。

**字体栈必须写楷体，而且 Skia 只认英文名。** 楷体有笔锋顿挫，是系统里最接近板书的中文字体；宋体是印刷体（横细竖粗带三角衬线），写在黑板上立刻假。栈里同时写 `KaiTi` 和 `楷体`：浏览器认中文族名，Skia（Node 端离线渲染）只认英文名，两端都得命中。**这一条有实测**——`0xEDGE` 那种"看起来很对"的助记符会直接把渲染器干崩，字体名写错的后果则是悄悄退化成宋体，画面上只是"没那么好看"。

**文字是逐字写上去的，不是整体淡入。** `writeChars` 按字符游标推进，每个字落笔时下沉 3.2px 再归位。所以"写字"这件事在时间上有先后，一眼能看出笔在走。整段淡入读起来是"翻页"，不是"写"。

**板框宽度必须小于内容左边距。** `frame: 52` 而 `x0: 104`，木框不会压到任何文字。这不是排版偏好——v2 的 `SW = 1240` 配 1080 画布，标题从 `x = 40` 起笔、推近后落到 `x = -45`，「析构函数」掉了一个「析」，正是没有这层约束。v4 把这条写成了断言。

## 已知缺陷

这张卡记下来，复用前先看一眼。前三条会实际阻碍迁移：

| 缺陷 | 位置 | 说明 |
|---|---|---|
| **楷体依赖系统字体** | `F_CHALK` | Windows 有 `simkai.ttf`，macOS 有 `Kaiti SC`，多数 Linux 发行版没有，会落到 SimSun。落下去之后"手写"变"印刷"，整套风格的气质就没了。要跨平台必须先装字体或内嵌子集 |
| **字号 16 种，没有令牌体系** | 全文 | 26/28/30/32/34/36/38/40/42/44/46/50/58/68/132/136。03 的缺陷表批评过"十余种临时值"，这一版又犯了。26–34 那六档其实可以并成两档 |
| **时间窗口全是手调数字** | 各镜的 `seg(p, a, b)` | 0.34、0.42、0.56… 没有节奏函数。改镜长或增删一句要重算全镜的窗口，而且算错了不报错，只是"字没写完" |
| 板擦是个方块 | `drawEraserMoving` | 252×122 的圆角矩形在平移，没有角度、没有手、不随扫动倾斜。静止看还行，动起来像"一个长方形在滑" |
| 板面没有"上一节课的字" | `drawDirt` | B01 擦的只是抽象灰痕。真实黑板擦掉的是字，所以"擦板"这个动作的叙事力度比设计时弱了一档 |
| 粉笔不会变短 | `drawChalkStick` | 八镜下来槽里的粉笔长度不变，和"一直在写"矛盾 |
| `drawAskAxis` 双层归一化 | `drawAskAxis` | 参数 `p` 是父级传进来的 reveal（已归一化一次），内部又用 `seg(p, 0.60, 0.86)` 切一次。踩过一次坑：注解只写了 6 个字就断了，因为窗口实际只剩 170ms |
| 楷体的全角标点留白 | 所有带 `？` 的行 | 楷体 `？` 占满一个 em，句末明显空一块 |

后五条不影响迁移，是这一版的欠账。前三条如果要长期复用，建议先解决。

## 什么场合用

- 要表达**推导过程**而不是结论：先这样、发现不对、改成那样。纸面和仪器都只能给"最终状态"，黑板能给"修改动作"。
- 要表达**"这条是错的"**：划掉是一种声明，红粉笔两道斜线压在字上，比任何图标都直接。
- 有**教学、讲解、复盘**的语境。板书天然带"有人在写"的在场感。
- 题材本身有**代码或公式**，而且需要指着某一行说事。
- 需要**中文字多**的画面。楷体在中等字号下依然清楚，这是荧光绿和细等宽做不到的。

## 什么场合别用

- **要展示"精致"。** 粉笔是糙的，边缘发毛、有颗粒、会断。适合表达"想清楚的过程"，不适合表达"做完了的成品"。
- **要表达数据或精确量。** 手绘的线和手写的数字天然不精确，画一条"上升 37%"的曲线会显得不可信。
- **横屏或宽画幅。** 这套版面是按 9:16 竖屏排的：内容区 872px 宽、垂直分三段（标题带 560–800 / 主体带 850–1450 / 落款 1480–1700）。改成 16:9 要重排版面，不是改个常量的事。
- **需要多元素并置对比。** 同时摆六个方框会被粉笔的粗糙感拖成一团。要并置就用 02 的纸面或 03 的仪器。
- **没有楷体的环境。** 见「已知缺陷」第一条，这是硬门槛。

## 换个题材怎么改

这套骨架的核心不是"黑板"，是**"写—划—改"这个动作序列**。所以迁移时保的是动作，换的是内容：

1. **先定"被划掉的是什么"。** 这是整条片子的支点：B03 写下的那行一定要是"看起来对、其实漏了"的写法。换成别的题材，就是"旧的方案"、"直觉的做法"、"上一版的假设"。如果被划掉的东西不值得划，整条片子就散了。
2. **再定"改成什么"，并给它一个颜色。** B06 用蓝色区分"改写后的正解"。换题材时颜色可以换，但必须和"错的那个"（粉）明确区分——两笔颜色接近，观众会读成"又写了一遍"而不是"改对了"。
3. **把论证画成一条线。** B02 的时间轴（拿到 → ？→ 还回去）、B04 的断叉、B07 的绿色回路，本质是同一条线在三个状态：完整、断掉、闭合。换题材时先画这条线，再决定它在哪里断。**这条线是全片的骨架，比文字重要。**
4. **换掉代码行，保留书写节奏。** `FILE* f = fopen(...)` 可以换成任何一行"有副作用的操作"：`conn = db.connect()`、`lock.acquire()`、`buf = malloc(n)`。每行控制在 20–28 个字符，超过就要缩字号或拆行。
5. **改课程号与标题。** `第 4 课` 和「资源去哪了？」是占位符，换成你的编号和问题句。标题控制在 5 个字以内、问号收尾——这一版所有视觉重量都压在标题上，六个字以上会撑破内容区。

不要改的是：**笔触的三层结构（划痕笔芯 + 外缘灰 + 淡底子）、楷体字体栈、逐字书写、板框小于内容边距**。这四条决定了它"像粉笔"而不是"像手写字体"。

改造时顺手把「已知缺陷」前三条一起处理掉——尤其是字号收敛和窗口函数化，越往后改成本越高。

## 风格引导块

换题材时不用重读上面全部，把这段整块复制走即可——喂给 AI 是风格约束，落成代码是常量表。

```
视觉：教室黑板，墨绿板面 + 木质边框 + 底部粉笔槽。
板面 #25332C→#1E2B25→#16211C 斜向渐变，四角径向压暗 30%。
边框 52px，胡桃木色 #3B2A1E，带竖向木纹；槽里放粉笔和板擦。
粉笔色：白 #EDEAE0（正文）、黄 #E8D48A（重点）、粉 #E89E9E（错误/划掉）、
蓝 #9BC0DC（改写）、绿 #A9C89C（通路/成立）。
笔触：一条线不是实线，是沿弧长撒的短划痕拼成——
段长 5–11px、间隔 1–3px、粗细和透明度都抖动；外缘再撒一层更淡的当粉笔灰。
字：楷体（KaiTi / Kaiti SC），逐字写出，落笔时下沉 3px 再归位。
动作：先写、再划掉、旁边重写。划掉是红粉笔两道斜线，压在字上。
不要：blur 阴影、发光、圆角卡片、无衬线细体、任何"科技感"的点线网格。
```

配套的四条硬约束：

- 笔触断续只能用"短划痕拼"，**不能用 `destination-out`**——它挖掉的是像素，导出 PNG 会变透明，合成进视频就是黑斑。
- 字体栈必须显式写 `KaiTi` 和 `楷体` 两个名字：浏览器认中文名，Skia 只认英文名。少了哪个，一端会退化成宋体。
- 木框宽度必须小于内容左边距（52 < 104），否则文字会被框切掉，而且屏上很难一眼看出来。
- 标题不超过 5 个字，字号 132；正文代码不超过 28 字符，字号 36。超了就缩字号或拆行，不要压边距。
