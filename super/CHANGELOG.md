## [1.9.0] - 2026-10-30

第五种风格「暖摊灯箱」。前四种换的都是**表面**（发光屏 → 纸 → 玻璃 → 粉笔灰），这一版换的是**光的方向**：不是光照在表面上，是表面自己发光——背光亚克力灯箱板。

动机来自一支 60 秒竖屏 B2B 短片（受众是销售同行，不是终端客户）。要的词是"热乎"，而"严谨/对比/推导"那三套都不给温度：纸和玻璃都是被照亮的，只有灯箱是自己亮的。

### 关键技术点

**灯箱是亮的，不是暗的。** 第一版按"焦糖黑底 + 暖黄光"画，深墨字压在深棕上完全没有对比，一屏糊。反过来之后——奶油琥珀底 + 深墨字 + 四角压暗——才成立。判断顺序必须是先定"这东西是亮的还是暗的"，再调色。

**灯箱上的纸必须比板暗。** 纸挡光。第一版用 `#DCC49A` 压在中段板色 `#E9C892` 上，明度几乎一样，四张通知单糊成四块"没加载出来的占位图"，反倒胶带最显眼。改成 `#C9A468` + 上沿深边 + 下沿 5px 亮边，立刻是"贴着纸的灯箱"。由此推出一条通用规则：**在这个介质里，所有附着物都比板面暗、且下缘亮；画得比板亮的，读者会当成光源。**

**记号笔和粉笔的参数是反的。** 同一套"笔画"代码：粉笔段与段之间空 2–4px 才断续，记号笔必须重叠 38% 才连续。硬记一条口诀——粉笔靠"留缝"，记号笔靠"叠压"。

**蒸汽硬边靠宽度差消，不靠 blur。** 三代才成立：等宽描线（白面条）→ 锥形单层渐变（左右硬边，像竖直光柱）→ 锥形三层同位叠加（宽度比 2.10 / 1.42 / 1.00，权重 0.15 / 0.32 / 1.00）。`shadowBlur` 一帧几十毫秒，1800 帧付不起，写进了禁用清单。

**实物剪影的身份靠内容物。** 纸袋画了两版都被读成"一次性纸杯"：一版错在袋口画了宽翻边（杯唇），一版错在袋底宽给了 0.44（那是圆锥）。真修法是袋底宽 0.82 + 按 z 序画三层（后片 → 暗口 → 袋里的栗子 → 前片）。**袋里有东西，就不可能被读成杯子。**

## [1.8.0] - 2026-10-29

第四种风格「黑板粉笔」。前三种换的是**仪器**（发光立方体 → 印刷版面 → 示波器），这一版换的是**介质**：不是屏幕，是粉笔灰。

动机不是"再来一种配色"，是前三种都做不到的一件事——**改**。纸面上的字印好了就不动，示波器只能测量不能反驳，只有板书能在写完一句之后说"这句不对"，划掉，在旁边重写。RAII 恰好是这样一条推导链，所以这一版的动词是「写」和「划」。

### 新增
- `renderer/src/board-renderer.js`（1354 行）：八镜 B01–B08，每镜 4 秒，共 32 秒。
- `renderer/board.html`：可交互工作台。切镜、逐帧、拖时间轴、导出单帧/整镜序列，另加**安全区**与**帧号**两个开关。
- `docs/cases/04-黑板粉笔.md`：八节案例卡 + 风格引导块，含 8 条已知缺陷。
- `docs/samples/style-04-blackboard.jpg`：展示台样品帧，540×960，由真实渲染器出帧后缩图。
- `tests/board.test.mjs`：12 项断言。
- `scripts/render-offline.mjs` 加 `--style v2|v3|v4`，三种风格共用一个出片脚本。
- 展示台第三张卡，网格从两列改三列；`npm run dev` 输出加黑板入口。

### 关键技术点

**粉笔的笔芯是短划痕拼的，不是一条实线。** 这是整版的支点。一条 `stroke()` 画出来的线，边缘再怎么抖也是马克笔。做法是沿弧长撒短划痕——段长 5–11px、间隔 0.6–2.8px、粗细与透明度各自抖动——叠出来天然断续、有颗粒；外缘再撒一层更淡的当粉笔灰。三件事一起做才有"粉笔写在粗糙表面"的质感。

**断续不能用 `destination-out`。** 第一版就是用它把线挖断的，视觉上最像粉笔。但它挖的是像素本身，导出 PNG 时变成透明，合成进视频就是一片黑斑——而且缩略图上看不出来，只有放大到 100% 才发现。改成短划痕拼之后既保住了质感又没了这个问题，顺手写成了断言。

**楷体是这一版的命门。** 宋体是印刷体（横细竖粗带三角衬线），写在黑板上立刻假。实测确认 `KaiTi` 在 Skia 里命中、`楷体` 不命中——浏览器认中文族名，Skia 只认英文名，所以两个字都得写进栈里。同时记进缺陷表：多数 Linux 没有楷体，会落到 SimSun，整套风格的气质就没了。

**木框宽度必须小于内容边距。** v2 的 `SW = 1240` 配 1080 画布，标题起笔在 `x = 40`、推近后落到 `x = -45`，「析构函数」掉了一个「析」。这一版把这个约束写成了断言（52 < 104），并且断言"所有文字都画在板面之内"。

### 修正
- **逐字书写把「进度」当成了「字数」。** `writeChars` 的第五个参数是"写到第几个字"，但各调用点传的是 `seg(p,a,b) * 某个魔数`，算出来是 0–1 的归一化进度。结果三行候选答案每行只画出了第一个字（`m` / `c` / `没`），而画面上看起来只是"没写完"。改成统一的 `chars(p, a, b, text)`，字数从文本自己来。
- **局部重绘漏了暗角，画面上亮出一个矩形。** `cleanPatch` 只填了板面渐变，没补那层径向压暗，所以擦出来的区域比周围亮一档，边界清清楚楚。抽出 `vignetteGrad` 让两层同进同退。
- **注释永远出不来。** `drawCode2` 的注释进度是 `r - 代码字数 - 2`，而 `r` 的上限就是"写完代码"，减完必然为负。改成独立的时间窗口。
- **脏污开关写反了，于是每镜都在画擦痕。** `drawBoard` 用的是 `if (opt.dirt !== false)`，只有 B01 传了 `dirty`，其余七镜压根没传这个字段——所以那两条"刚擦过"的横向亮带在 B02–B08 每镜都画了一遍，压在写满字的画面上就是两条不明所以的白带。改成 `opt.dirty === true`，只有擦板那一镜才脏。
- **板擦绒布纹把擦除区提亮成一枚方形补丁。** `cleanPatch` 里 14 条 `0.012–0.032` 的浅色细纹叠在小面积里，整体亮度被抬上一档，矩形边界清清楚楚。减到 8 条、alpha 压到 `0.005–0.015` 才只剩"擦过"的暗示。
- 红笔划掉的两道线各自加重（`5.2→6.4` / `4.2→5.4`，alpha `0.92→0.95` / `0.78→0.85`）：原来的粗细在 1080×1920 上放出来，"划掉"这个动作读不出来，看起来像两道划痕。
- **帧号水印默认开着，正片里就是瑕疵。** 改成默认关，工作台可手动打开，`exportFrame` / `exportSequence` 内部强制关。
- **`ffmpeg` 调用只在 PATH 里找，合成静默失败。** 错误提示里还写了个不插值的 `'${STYLE}_%04d.png'`，说明这段代码从没被真正执行过。改成先看 `FFMPEG` 环境变量，报错时把实际命令打出来。用 `FFMPEG=D:/Tools/ffmpeg/bin/ffmpeg.exe` 跑通了端到端。
- CI 的 `node-version` 从 20 提到 22：`tests/_env.mjs` 用了 `import.meta.dirname`（20.11+），留在 20 上会出现"本地绿、CI 红"。同时把语法检查补到三个渲染器和两个脚本。
- 两条硬编码名单的断言改成动态扫描：展示台样品图从页面里抽，现役卡从 `docs/cases/` 里扫。写死过一次，04 加进来时根本没被检查到。

### 变更
- `tests/_env.mjs` 的 `measureText` 桩开始按字号估算宽度（中文 1em、ASCII 0.55em）。之前一律返回 `length * 12`，字号 132 的标题会被低估十倍，"文字有没有超出板面"这类断言形同虚设。
- README、验证记录、案例索引同步到三风格 / 65 项。

### 记录
- **这一版的笔触方案是"选"出来的，不是"想"出来的。** 做了四组对照：仅抖动（像马克笔）、抖动+散粒（方框像了，斜线还是实）、抖动+散粒+挖洞断续（最像，但有透明洞）、短划痕拼笔芯（保住了质感又没洞）。前三组都写成了可运行的对照图，最后才定。**质感这类东西不能靠描述决定，得排出来看。**
- **竖屏构图的第一版是失败的。** 标题只占上方四分之一，下面 2/3 全空。原因是把"标题"和"内容"都挤在 300–900 之间，而画布有 1920 高。后来的解法不是把字放大，是**给每一镜都排满三段**（标题带 560–800 / 主体带 850–1450 / 落款带 1480–1700），空着在 4 秒的镜头里读起来就是"没写完"。
- **"已擦除"和"没画"看起来是一样的。** B07 的方块被擦掉、B08 整块板面被擦干净，一开始都直接不画，结果画面像是"东西凭空消失了"。加了一层 `cleanPatch`（干净板面 + 淡横向绒布纹）之后才有"擦过"的痕迹。
