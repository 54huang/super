## 三、为什么这样分类

抖音短视频的实际生产链路是：**一句话想法 → 脚本/口播 → 分镜（几秒一镜）→ 单镜提示词（画面+镜头+质感+约束）→ 出片**。
这 50 个仓不是按「模型名」硬分，而是按**你在链路的哪一步需要它**分，所以同一部片子会同时用到 01/02/03/04/05 五个目录里的东西，但不会重复。模型专用的仓单独放 05，因为换模型时只有这一层需要重写。

判断一个仓值不值得收，用四条：
1. 内容是不是**文本资产**（提示词/词表/模板/Skill 的 md），而不是权重或成片；
2. 有没有**镜头维度**（景别、运镜、机位、焦段、时长），而不只是「画什么」；
3. 能不能**原样粘贴**进模型（纯净、可复制、不夹带平台推广）；
4. 是否**仍在更新**（2026 年仍有提交优先）。

## 四、9:16 竖屏的 5 个硬约束（用这些仓时始终记着）

1. **时长按平台能力切**：单镜 4/6/8/10 秒是多数模型的上限，分镜时先算时间轴，再写画面（`geeklee/srt-vox-director` 就是按这个逻辑做的）。
2. **首帧决定完播**：竖屏没有宽幅留白，第一帧必须有主体+对比+信息量，提示词里要把「首帧构图」单独写一句。
3. **字幕安全区**：底部约 15%、右侧约 12% 会被 UI 遮挡，分镜时人物主体与关键动作避开这两条带。
4. **一镜一动作**：竖屏镜头切换快，一个镜头里塞两个动作（走+转身+说话）几乎必崩，宁可用两条提示词。
5. **跨镜一致性靠锚点**：人物外观、服装、光源方向、色调要写成固定字符串，每个镜头原样复制（各 Skill 里的「一致性锚点/视觉圣经」就是干这个的）。
