## 为什么是节点

N24 是把片子拆成"画面 + 音频 + 脚本"，它是把片子拆成**可执行的生产任务**。关键差别在输出契约：它区分「首帧提示词」和「动态提示词」，一镜一条生成任务，硬切镜各配各的首帧。这正是图生视频模型的输入习惯，也是反推最容易漏掉的一层。

## 它能给你什么

1. **四种模式，选错就白跑**：

   | 模式 | 什么时候用 | 交付什么 |
   |---|---|---|
   | AUTO | 不确定 | 自己按外观和时间信息选路线 |
   | T2VA | 只要一段完整提示词 | 自包含的全片描述 + 三字段 Prompt |
   | I2V | 先锁外观再动作 | 每镜首帧/首尾帧 Prompt + Motion Prompt + 装配说明 |
   | DUAL | 整体和逐镜都要 | 同一份事实表出两套版本 |

2. **"一段提示词"是排版，不是生产单元**：I2V 里每个真实硬切仍是独立生成任务、独立首帧。这一点很多反推工具含糊过去了，它写在输出契约里。
3. **长片按段落组织**：超过平台单次时长上限就拆任务，给出"源时间映射 + 交接人物/道具/动作状态/连续音轨"。
4. **规矩很硬**：中文解释、英文 Prompt；对白与画面文字保留原语言；**未核实的内容不许补写**。最后这条把"反推变成编造"的路堵住了。

## 抖音 9:16 用法

- 反推对标账号时用 I2V：它会把每条镜头拆成"首帧长什么样"+"怎么动"，竖屏首帧的构图（主体占几成、留白在哪）能被显式记录下来。
- 改编请求直接写进指令，比如"改成 10 秒一镜到底，保留主角身份和动作先后，允许用收紧景别替代切镜"——它会把原片与改编的差异、以及时长变化后原声怎么处理一并交代。
- 30 秒以上的口播片按 30 秒段落反推，段落之间交接"人物、道具、动作状态"，避免第 2 段人物换脸。

## 取用路径

1. 先读 `README.md` 的中文教程，搞清四种模式的差别（三分钟）。
2. 投视频 + 一句话指令：`完整检查附件视频，输出 I2V。保留真实镜头，不压缩时间。每镜给独立首帧提示词、动态提示词和镜间装配说明。`
3. 拿到首帧提示词后回 03 目录补质感，动态提示词回 02 目录补运镜。
4. `scripts/` 里有校验脚本，反推结果可以先自检一遍再拿去生成。

## 注意

- 它的字段是按海螺 H3 的输入习惯写的。换 Seedance / Veo 时字段要改，方法不变。
- 反推的前提是**看得清**：压缩严重、字幕压身的片子，它会拒绝补写（这正是对的），此时先换条清晰片源。
- 它不判断内容好坏，只做还原。要不要复刻是另一个问题——结构可以借，主体必须换，否则就是搬运。
