## 为什么是节点

它把"非生成式"这条路做成了**完整的产品闭环**：一句场景提示词 → 拆成 shot sheet（分镜表）→ 编码 agent 用 HTML 把整片画出来。**全程不调用视频模型**。`films/` 里有成品可以直接看质量，`harness/` 是渲染管线。

## 它能给你什么

1. **shot sheet 的结构**：这就是 04 目录分镜表的一个可执行版本 —— 每镜包含画面描述、时长、转场、图层。
2. **`films/` 成品**：先看能做到什么水平，再决定要不要投时间。
3. **手绘/线稿/水墨风格**：这条路最擅长这类画面，而且**风格极其稳定**（因为是代码画的，不会漂）。
4. **可迭代**：改一个参数重渲染，比重新生成一条视频便宜得多。

## 抖音 9:16 用法

- 做**国风/水墨/线稿/讲解**类内容最合适，这类在抖音上辨识度高、且不撞脸。
- 画布 1080×1920，转场时长控制在 0.3-0.5 秒（代码转场比 AI 转场干净）。
- 每一镜的动作要写"从 A 状态到 B 状态"，代码才能插值；写"角色很伤心"无法执行。
- 配音与字幕另外叠，别指望它一次出完整音画。

## 取用路径

1. `films/` 看 1-2 个成品。
2. `skills/` 读"提示词 → shot sheet"的规则。
3. 用 `harness/` 渲染自己的第一镜。

## 注意

需要能跑 Node 环境；纯内容创作者可以让编码 agent 代跑。这条路的门槛不在创意，在"能不能描述清楚状态变化"。
