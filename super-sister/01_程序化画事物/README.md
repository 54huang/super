# 01 · 程序化画事物

> 这一层解决**轮廓从哪来**：山、树、人、街上的砖、画到一半的线稿。它决定"像不像那个东西"。
> 特点是**没有原图**——一切都由函数生成，所以任何参数都能连续变，能出动画，也能同种子复现。

**收录逻辑**：能读、能跑、能拆的**画法实现**。不是画图 API 的封装，而是"这个形状凭什么长这样"的那部分。
**什么时候来**：AI 生成怎么调都画不像某个具体东西（比如一袋栗子、一段手写纸条）；或者你要的是"线条自己在生长"这种非写实动作；或者同一套画面要量产几十集但每集不一样。

## 取用顺序

1. **先定"这东西由哪几块构成"**，再找画法。例：一袋糖炒栗子 = 袋身（四边形 + 折痕）+ 袋口（暗椭圆）+ 内容物（若干个带高光的椭圆）+ 蒸汽（三层叠加）。拆完你会发现没有任何一个库直接给你"栗子袋"，但每一块都能从上面的仓里拼出来。
2. **自然物 → 01**；**几何物/线稿 → 03**；**手绘感 → 04**；**笔顺序 → 05**；**不规则边 → 06/07**；**排列 → 09**。
3. **同一套东西要量产**：把随机全部收进种子（06/07），把尺寸全部写成相对比例（别写死像素），这样换画布尺寸不重画。

## 三条关键认知

- **"像"来自分层，不来自细节。** `shan-shui-inf` 的山只用 500 个点，但分了 10 层（近浓远淡）；一袋栗子像不像，取决于"袋—口—内容物"三层有没有画全，不取决于高光画得多细。
- **不要用模糊做柔边。** 烟、光、影要柔，靠"多层同位叠加 + 每层宽度不同"，不靠 `shadowBlur`。模糊在逐帧渲染里是纯成本：一帧几十毫秒 × 1800 帧，等于多花几个小时，还换不来正确的结果。
- **画法比库重要。** 这 10 个仓里 6 个是库，但你真正要抄的是"那几十行怎么算的"。抄完就把包删掉，直接搬进自己的渲染器——依赖越少，竖屏改尺寸时越不会崩。
