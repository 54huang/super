## 为什么是节点

因为**没有任何一个绘图库管"顺序"**。

你从 N01 或 N03 出来的 SVG，线段集合是按生成顺序排的——而生成顺序通常是"先算远的后算近的""先画所有树的树干再画所有叶子"。人不是这么画的。人是一棵树画完再画下一棵，一笔能连着的就连着走。

`vpype` 干的就是把"一堆线"变成"一只能画出来的手"：合并共线、简化折点、按最近邻排序、把能连的连成一条路径。

## 它能给你什么

1. **`linemerge`**：首尾相接的线段合成一条连续路径。不做这一步，你的"线条生长"会在本该连贯的地方断掉。
2. **`linesort`**：按最近邻重排路径顺序，把笔的移动距离压到最小。**这是"画得像人"的关键一步**——不做它，线条会在画面上满屏乱跳。
3. **`linesimplify`**：在保留形状的前提下删掉多余折点，线条变干净、渲染变快。
4. **`reloop`**：在路径中找闭合回路并断开重排，让"同一笔"连贯。
5. **`vpx`（`vpype_viewer/`）**：可视化每一笔的顺序与颜色，调参时不用猜。
6. **它是管线式的**：`vpype read in.svg linemerge linesort write out.svg`。你要做的加工就是一条命令链，容易嵌进脚本，也容易在逐帧渲染里跑（但注意：它慢，见下）。

## 怎么落到 9:16 竖屏

- **顺序决定"生长动画"的观感**。竖屏观看时眼睛从上往下扫，所以 `linesort` 之后最好再按 y 坐标粗排一次——否则线条会来回上下跳，很晕。
- 做"逐笔画出"时，**每笔的时长按长度分配**，不要按笔数均分：短笔 80ms、长笔 400ms，均分会让长笔太快、像在闪。
- 1080 宽画布上，`linesimplify` 的容差取 0.6–1.0 像素。再大就变形，再小就没效果。
- 笔与笔之间的**抬笔移动要留 0.15–0.2 秒空白**，人才觉得"这是两笔"。

## 取用路径

1. 先跑通 `vpype read 文件.svg linemerge linesort write out.svg`，看输出 SVG 的路径数少了多少。
2. 用 `vpx` 看顺序色带（它按顺序给每笔上渐变色）——一眼就知道排得对不对。
3. 需要按区域分批画（比如"先画背景再画主体"），用它的图层功能，一个图层一条命令链。
4. 读 `docs/` 的命令表，别猜命令名。

## 注意

- **它是 CPU 单线程的 Python**，一个几万段线的 SVG 跑一遍要几秒。做 1800 帧动画时**不能每帧都跑**——正确做法是：跑一次得到顺序，把这个顺序固化进你的渲染器，之后每帧只按顺序画。
- 本仓只处理 2D 线（SVG/HPGL），没有颜色与填充的概念，它眼里只有"路径"。
- **它是最好的"后处理"工具，不是绘图工具**。别指望它画东西。
