## 为什么是节点

因为**合成器做不出"真钢琴"**，而真钢琴采样通常要几个 GB。

这个仓把通用 MIDI 的 128 种音色按音高切成单个 mp3，托管在 GitHub Pages 上，**浏览器可以按需只加载用到的那几个音**。做"钢琴独奏的垫乐""弦乐底"这类需要真乐器质感的段落，这是最省事的一条路。

## 它能给你什么

1. **三个音色包，质量递增**：`FluidR3_GM`（148MB 原始 sf2 渲染，体积小、够用）、`MusyngKite`（1.75GB 原始，明显更真）、`FatBoy`（320MB，偏厚）。**先用 FluidR3 试，不满意再换。**
2. **URL 规则简单**：`https://gleitz.github.io/midi-js-soundfonts/FluidR3_GM/{乐器名}-mp3.js`，乐器名清单在 `names.json`。**可以只取需要的几个音**，不用整包下载。
3. **`Tabla/`** 是打击乐（印度塔布拉），映射到 `synth_drum` 用——做"手鼓/木质敲击"底时比合成器自然。
4. **配合 N11 的 `Sampler`**：Tone.js 的 `Sampler` 能按音高映射采样，这几个包的数据结构正好对得上。

## 怎么落到 9:16 竖屏

- **竖屏片通常只需要一种乐器**。选一个（钢琴 / 弦乐 / 尼龙吉他），只加载那个音色的 3–4 个八度，体积就不是问题了。
- 真乐器采样**不能拉伸太多**。同一个音色，`Sampler` 的音高偏移超过 ±2 个半音就会明显失真——所以要加载足够密的音高。
- **垫乐不要用真钢琴弹密集和弦**。手机喇叭放不出低频，密集和弦会糊成一片；改成单音 + 混响，或者两个音的三度/五度。
- 音量还是那条：比人声低 12dB 以上（按 RMS 算，不是峰值）。

## 取用路径

1. 读 `README.md` 的 URL 规则，先手工 fetch 一个音试试（`marimba-mp3.js` 是例子）。
2. 在 Tone.js 里用 `Sampler` 挂上，设置 `urls` 映射（音名 → 文件）。
3. 只加载用到的音高 → 体积可控。
4. 导出时**不要用它实时渲染**：音色包是"给浏览器播放"的，出片要离线渲染（把 mp3 解码后拼成音轨）。

## 注意

- **许可是本节点最容易搞错的地方**：仓库根目录 `LICENSE.txt` 写的是 MIT（那是打包脚本的），但**音频文件本身**在 `README.md` 里逐包声明了 CC BY 3.0 / CC BY-SA 3.0。
  - **CC BY 3.0**（FluidR3）：商用可以，**要署名**（在片尾或说明里写一句来源）。
  - **CC BY-SA 3.0**（Musyng Kite / Fat Boy）：商用可以，要署名，**且衍生作品要同许可分发**。用在片子里（音色被混进成片音轨）通常不算"衍生音色包"，但**不要单独把这些音色文件再分发或打包卖**。
- 停更在 2021，数据不会再变（音色是死的），不算风险。
- 音色是 **mp3 编码**，做高质量成片时优先用 FluidR3 的原始 sf2 自己渲染，音质更好。
- **别把音色文件复制进仓库**。只记 URL 规则，用时现取。
