## 为什么是节点

因为**"字幕和语音差半拍"这个问题的唯一正解，是量出来，不是估出来。**

做片子的默认做法是：写完稿 → 估算每秒几个字 → 按估算排镜头和字幕。这个估算会差 20%（中文尤其，因为枚举、标点、短句都在吃时间）。

`librosa` 让你把这件事从"估算"变成"测量"：给它一条人声音轨，它能给出**每个字的起音时刻**（`onset_detect`）、**整条的速度与重拍**（`beat_track` / `tempo`）、**哪段是静音**。有了这些，字幕时间码、镜头切点、落点音位置全部可以按实测摆——而不是按字数除。

## 它能给你什么

1. **`onset_detect`**：起音检测。这是"每个字什么时候开始"的答案，也是**字幕时间码**的来源。
2. **`beat_track` / `tempo`**：节拍与速度。有配乐时用它找重拍，让画面切点落在拍上——这是"卡点"的算法版。
3. **`effects.split` / `silence` 相关**：按静音切段，找"句子之间"的停顿。做"每句一镜"时用它切，比手工拖时间轴准。
4. **`pyin`**：基频跟踪。做"跟着音高变形的图形"时用（这条比较进阶）。
5. **`stft` / `melspectrogram`**：频谱。做"声音可视化"（频谱条、波形动画）用它，比 Web Audio 的 AnalyserNode 更可控（因为可以离线批量算）。
6. **`load`**：直接读 mp3/wav/flac，不用先转格式。

## 怎么落到 9:16 竖屏

竖屏片的标准量测流程（一条命令一个结论）：

```
1. 逐句合成语音 → 得到 N 个 wav
2. librosa 量每句的真实时长（不要用字符数估）
3. 按实测时长排镜头窗口，留 LEAD 0.3s / TAIL 0.2s
4. onset_detect 找每句内部的重音，字幕按它切
5. 所有数字写进一个 align.json，渲染器和字幕生成器都读它
```

- 字幕**提前 0.12 秒出**、句末**多停 0.3 秒**——这是实测出来的经验值，不是审美。人眼读字比耳朵听音慢。
- 竖屏底部有 UI 遮挡，字太多会溢出：onset 拿到之后要**按字数二次压缩**，一句话拆成两条字幕时以 onset 为界、不以标点为界（标点处的停顿常常不够长）。
- 有了 onset，落点音可以**精确到帧**：在 onset 前 1 帧触发，观感上"声音和动作是一起发生的"。

## 取用路径

1. `librosa.load(路径)` → 拿到 `y`（波形）和 `sr`。
2. `librosa.onset.onset_detect(y=y, sr=sr, units='time')` → 起音时刻数组。
3. 对照你的稿子，把每句的起止填进 `align.json`。
4. 有配乐就再跑 `beat_track`，把画面切点对齐到最近的拍。
5. 想可视化就 `stft` → `amplitude_to_db` → 取每帧的列画成条。

## 注意

- **它是分析工具，不是合成工具**。别指望它造声音。
- 依赖 numpy/scipy/soundfile，装起来比较重（但比 prettymaps 轻）。
- `onset_detect` 在**语速快、连读多**的中文语音上会漏检——所以它给的是"候选点"，最终还得人过一遍。**别把它当全自动**。
- 静音检测的阈值（`top_db`）要按你的录音电平调，默认值在低声压录音上会漏。
- ISC 许可，商用无碍。
