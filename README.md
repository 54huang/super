# super · 全量备份（super + super-sister）

> 这个仓不是用来编辑的，是**只读备份**。真正的编辑发生在两个源仓库里，这里的内容由 `sync.mjs` 单向生成。

**远端**：https://github.com/54huang/super （备份）
**源仓库**（都在同一台机器的同级目录下，各自有独立远端）：

| 本仓目录 | 源仓库 | 源远端 | 是什么 |
|---|---|---|---|
| `super/` | `super` | `git.h06.cn/514140019/super` | 视频工作台的案例参考库：设计手法、已知缺陷、制作过程 |
| `super-sister/` | `代码视觉与音效素材库_24仓` | `git.h06.cn/514140019/super-sister` | 素材索引库：用代码画东西 / 背景材质 / 声音，24 仓 15 节点 |

两个源仓库各自独立、互不依赖。这个备份仓只做一件事：把两边的**已跟踪内容**合到一处，方便一处取用、一处存档。

---

## 为什么只有这么小

`super` 在你硬盘上有 **394MB**，但这个备份仓里只有几百 KB。原因是 `.gitignore` 已经把逐帧产物排除掉了：

```
frames/      381MB   逐帧 PNG
exports/       9MB   合成好的 mp4
```

**备份的是"内容"，不是"产物"。** 产物能用代码重新生成；把 381MB 帧序列塞进备份仓，只会让每次同步都推几百 MB，且没有任何恢复价值。

反过来，如果哪天 `.gitignore` 改了、产物被纳入跟踪，它们会自动跟着进来——这个脚本只认 `git archive`，也就是**认 git 承认的东西**。

## 怎么用

```bash
node sync.mjs                  # 同步 + 提交 + 推 GitHub
node sync.mjs --no-push        # 只同步 + 提交
node sync.mjs --install-hooks  # 给两个源仓库装 post-commit 钩子（此后每次提交自动同步）
```

装了钩子之后，在 `super` 或 `super-sister` 里 commit 完，会自动跑一次同步；**同步失败只打印一行警告，不会阻止你的提交**（网络断了不该让你提交不了代码）。

**幂等**：没有变化时第二次运行会直接说「内容与上次一致，无需提交」，不会产生空提交。判据是「源仓库的 `branch@sha` + 根目录手写文件」，不是树的哈希——`_state.json` 里有时间戳，用树比较会永远判定有变化（第一版就是这么写出重复提交的）。

## 一个必须记住的坑：GitHub 账号

这台机器的 git 凭据管理器里，`github.com` 默认用的是 **`cduking`**，但仓库属于 **`54huang`**。直接推会得到：

```
remote: Permission to 54huang/super.git denied to cduking.
```

解决办法（已经设好，在这个仓库的本地配置里）：

```bash
git config credential.username 54huang
```

**如果你换机器或凭据丢了，先设这一行再推。** 只读操作（`ls-remote`、`clone` 公开仓）不需要，因为那是匿名访问。

## 同步做了什么

1. `git archive HEAD` 把每个源仓库的跟踪内容导出（不是文件系统复制，所以不受未跟踪文件干扰）
2. 覆盖本仓的同名子目录（删干净再解，避免残留已删除的文件）
3. 写 `_state.json`：记录这次同步时每个源的 `branch@短SHA`、文件数、最后一次提交标题
4. 内容有变才提交，提交信息形如 `同步 super@94e146b + super-sister@ffd096e`
5. 推 `origin`

## 它不做的事

- **不带 git 历史。** 本仓每次提交是一个"内容快照"，两个源仓库的完整历史仍在各自的远端（gitea）。要连历史一起备份的话，得用 `git bundle`，那是另一套做法。
- **不做双向同步。** 在本仓改文件不会回流，下次同步会被覆盖。想改内容，去源仓库改。
